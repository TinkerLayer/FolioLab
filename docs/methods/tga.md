# TGA: methods and validation

This document describes what the TGA module (`modules/tga/`, module version 0.13.0) computes, how, with which
defaults and limits, which reference the code cites, and which automated test checks it. It is written so that you
can decide whether a number from this module is fit to report. Statements refer to the code in
`modules/tga/tga/*.py`; file names below are relative to `modules/tga/`.

All tests named here use **synthetic data** with known target values (generated by `tga/synth.py`, `tga/egs.py` or
inside the test). No test uses a real instrument file. Run them with
`python -m unittest discover -s tests` in `modules/tga`. Test identifiers are given as
`path::TestClass::test_name`.

## How to cite results from this module

State the Folio Lab version (`package.json`) and the TGA module version (`modules/tga/module.json`, field
`version`; also `tga.__version__`). When a result is sent to a report (**To report …**), the report stores the
measurement files and the request in the bundle. The report manifest records, under `provenance`, the Folio Lab version (`suite_version`), the module
version (`module_version`) and the SHA-256 of every stored measurement file (`source_sha256`). **Refresh** in the report
editor recomputes from the stored files with the module version installed at that time and keeps the previous
revision. Cite the methods named in the generated methods text with the references it adds to `refs.bib`; these
are the entries listed under [References](#references-as-recorded-in-the-code).

## Conventions

| Quantity | Unit and basis |
|---|---|
| Time *t* | min |
| Temperature *T* | °C (kinetics internally in K: *T* + 273.15) |
| Mass *m* | mg, or % of the reference mass (`Run.pct()`) |
| Reference mass | the value set by the processing step "reference mass", else the sample mass *m₀*. A file in mg without a sample mass gets *m₀* = median of the first five mass values; a file in % without a sample mass is used as it is (`readers.py`, `Run.pct`, `build_run`) |
| Losses, residues, composition | percentage points of the reference mass |
| DTG | dm/dt in %/min and dm/dT in %/°C; shown and searched as positive numbers for loss |
| Gas constant | R = 8.314462618 J/(mol·K), commented as CODATA 2022 (`kinetics.py`, `synth.py`) |

## 1 Reading files

**What is computed:** a run with time, temperature (sample temperature, else program temperature), mass and optional
extra columns (program temperature, instrument DTG, heat flow, gas flow, segment, gas). Code: `tga/readers.py`,
shared text helpers in `sdk/python/labtable.py`.

### Format detection

| Format | Detected by | Notes |
|---|---|---|
| Generic text/CSV | fallback | delimiter tab, `;`, `,` or space chosen by the most rows with the same number of numeric fields; decimal comma when tokens like `12,34` outnumber `12.34` and the comma is not the delimiter; the data block is the longest run of consecutive, mostly numeric rows (at least 5 rows); names and units from up to three lines above it (`Name [unit]`, `Name (unit)`, `Name/unit` or a separate unit row) |
| NETZSCH Proteus ASCII | a `##` table header plus `#KEY: value` lines | `##Temp./°C;Time/min;Mass/%` style header |
| TA Universal Analysis | `StartOfData` and `SigN` lines in the first 400 lines | column names from the `SigN` list |
| TA TRIOS XLSX | `.xlsx`/`.xlsm`; each sheet parsed as a table | if more than one sheet parses, all have a time column and the same mass unit, the sheets are joined in sheet order into **one** run with one segment number per sheet. If a sheet's first time is not after the previous sheet's last time (each sheet restarts its clock), the sheet's times are shifted so that it starts one median time step (of the previous sheet) after the previous sheet's end; time is then continuous and strictly increasing. The offsets are stored (`sheet_time_offsets`) and shown as a note |
| METTLER STARe TXT | first column name contains `Index` and a `Ts` column | time without unit and maximum > 600 is taken as seconds |
| PerkinElmer Pyris TXT | a column named `Unsubtracted …` | see mass-column choice below; the corrected (blank-subtracted) weight is preferred |
| Shimadzu ASCII | a line `[Data]` | |
| NETZSCH `.ngb-ss3`, `.ngb-bs3`, `.ngb-ds3` | file extension | only with the optional package pyngb (`requirements-optional.txt`: `pyngb>=0.6`); columns `time` (s), `sample_temperature`, `program_temperature` (°C), `mass` (mg), `dsc_signal` (µV), `dtg` (mg/min), `purge_flow`/`purge_flow_1` (ml/min), `segment`; units stored in the file take precedence over these defaults; `.ngb-ds3` is requested from pyngb as the corrected run (sample minus embedded correction) |
| `.001`, `.tri`, other ZIP-like files | extension or `PK` signature | refused with a request to export as text |

Text encodings tried: UTF-16 (with BOM, or detected by zero bytes), UTF-8, cp1252, latin-1.

### Assumptions the readers make

| Situation | What the code assumes |
|---|---|
| Time column without unit | minutes (METTLER exception above); `s`, `h`, `ms` are converted |
| Temperature column without unit | Kelvin if the column name contains a separate `K` (e.g. `Temperature K`, `T_K`) or `kelvin`, or if the median of the first five values lies between 250 and 330 (room temperature in K); otherwise °C. Both guesses add a note to the run (`meta.read_notes`, shown in the info line, the file panel and the column dialog); a column without unit that starts above 330 is read as °C with a note. A unit chosen in the column-mapping dialog overrides the guess. A run without unit that really starts between 250 and 330 °C is misread as Kelvin unless the unit is set |
| Temperature in K or °F | converted to °C |
| Mass column without unit | % if 50 ≤ max ≤ 120, min ≥ −5 and no sample mass in the header; otherwise mg |
| Mass in g or µg | converted to mg |
| Mass in % and a sample mass in the header | converted to mg with *m₀* |
| No sample mass anywhere | *m₀* = median of the first (up to) five mass values; recorded as `m0_from` |
| Mass-change column (name contains change, loss, verlust, delta or änderung, and the first values are near 0) | absolute mass = *m₀* + Δm; refused if *m₀* is missing |
| Several mass columns | scored: name does **not** contain "unsubtracted"/"uncorrected" +3, name contains "corrected" +1, unit mg +2, g +1, % +0.5, name contains change/loss −2; columns named baseline/blank are ignored. For PerkinElmer files the corrected weight (e.g. `Weight`) is therefore used; the unsubtracted weight only if no other mass column exists, with a note "ohne Leerkurvenkorrektur". The chosen column is stored as `meta.m_column` and shown in the file panel |
| Several temperature columns | the one named sample/Probe/Ts is the sample temperature; the next becomes program temperature |
| Columns without names | 2 columns: T, m; 3 or more: t, T, m (marked as guessed) |
| Heating rate | from the header (a number followed by K/min, °C/min … in a line that mentions rate, heating, range, ramp, segment, method or a "to" range); else the median of dT/dt over points with \|dT/dt\| > 0.3 K/min, rounded to 0.1 K/min, only if positive |
| Header metadata | sample mass, gas(es) in order of appearance, crucible, instrument, sample name, date, operator, flow (ml/min) |
| Plausibility | at least 5 valid points; sample temperature must lie between −200 and 2500 °C |

The column-mapping dialog overrides all role and unit guesses.

## 2 Processing protocol

The protocol is a list of steps, always applied to the original run in the same order (`tga/process.py`, `apply`).
Interface, export and report use the same code.

| Step | Computation | Defaults and limits |
|---|---|---|
| Reference mass (100 %) | m% = m / m_ref · 100. m_ref: *m₀* (or median of the first 3 values); mass at the first point with T ≥ T_ref (no interpolation); mass after time t (linear interpolation); or a value in mg | T_ref default 120 °C; refused if m_ref ≤ 0 |
| Cut | keep points with lo ≤ T (or t) ≤ hi | default 30–900 °C; at least 10 points |
| Keep segments | keep the listed segment numbers (see segment detection) | at least 10 points |
| Temperature calibration | T′ = a + b·T, applied to sample and program temperature | a = 0 K, b = 1; refused unless 0.5 < b < 1.5 |
| Buoyancy correction (linear) | m′ = m − c·max(0, T − T₀); in % mode the term is divided by *m₀* | c in µg/K (default 0), T₀ default 25 °C. c is entered by the user; it is not fitted |
| Smooth mass | Savitzky–Golay (least-squares coefficients from a Vandermonde pseudo-inverse; ends padded by point reflection) or moving mean (ends padded with the end values) | 11 points, order 2; window 3–301, odd |
| Resample | uniform time grid; continuous columns interpolated linearly, segment and gas columns take the next sample | step 0.1 min; refused above 200 000 points |
| Convert to mg | m_mg = m% · m_ref / 100 | needs a reference mass in mg |

Smoothing the mass and then computing the DTG (section 3) applies two Savitzky–Golay filters in series.

### Blank subtraction and averaging (derived runs)

In the **Compare** tab two further operations create a new run (`server.py`, `derive`). The result is written in
the module's CSV format and loaded like a file; its header records the origin.

- **Blank subtraction:** m_corr(x) = m_sample(x) − [m_blank(x) − m_blank(x₀)], with x = T or t, the blank
  interpolated linearly at the sample's x values. On the temperature axis only the first heating of the blank is
  used (points where T reaches a new maximum). Outside the blank's range the end value of the correction is held
  constant (`numpy.interp`). Sample and blank must have the same mass unit.
- **Average:** each run's % curve (first heating) is interpolated on the first run's temperatures and averaged with
  `nanmean`; where fewer runs cover a temperature, the mean is over fewer runs. The result is in %.

### Segment detection

`process.segments`: the heating rate is the gradient of the program temperature (else sample temperature) after a
moving mean over about 0.5 min. Points with rate > 0.3 K/min are heating, < −0.3 K/min cooling, otherwise
isothermal. Segments are also split where the file's segment or gas column changes. Pieces shorter than 0.4 min are
merged into a neighbour with the same gas. The first gas change (from the gas column) is used by the composition
templates.

**Reference:** Savitzky & Golay (1964), cited in `process.py` and added to every report. No reference for the other
steps.

**Validation:**

- `tests/test_tga.py::StepTest::test_pipeline_ops` – reference mass at 120 °C gives 100 % ± 0.2 near 121 °C; cut
  leaves T ≥ 50 °C; four steps are recorded. The calibration step is run with a = 1, b = 1 and the smoothing step
  with default parameters; neither result is compared with an expected value.
- `tests/test_tga.py::StepTest::test_segments_and_gas_switch` – the synthetic N₂ → air run gives at least two
  segments and a detected gas switch.
- Not covered by a test: buoyancy correction, resampling, conversion to mg, blank subtraction, averaging.

## 3 DTG

`process.dtg`: the mass in % is differentiated with a Savitzky–Golay first derivative over the point index (order 2),
and so is time (order 1); dm/dt = (dm/di)/(dt/di). dm/dT uses the same quotient with the derivative of temperature.

- Window in points: round(width / β / Δt), with width = 4 K (default), β the heating rate from the file
  (10 K/min if unknown) and Δt the median time step; clipped to at least 5 points and at most n/3, forced odd.
- dm/dT is undefined (NaN) where |dT/dt| < 0.3 K/min (isothermal parts).
- Fewer than 7 points: DTG is zero.

**Reference:** Savitzky & Golay (1964).

**Validation:** indirect, through the step tests in section 4 and the golden test
`tests/test_golden.py::GoldenBundle::test_bundle_en`, which pins the exported DTG column `dtg_pct_C` of the synthetic
oxalate run (first and last row).

## 4 Step detection

`steps.detect`, defaults in `steps.DEFAULT`:

1. Loss rate r(t) = −dm/dt (%/min).
2. Candidate steps are local maxima of r with a prominence of at least `rel` = 3 % of the largest rate.
3. Limits: between two peaks, the rate minimum between them; at the outer edges, where r falls below
   `edge` = 5 % of that peak's rate.
4. Steps with loss < `min_loss` = 0.3 % are removed one at a time (smallest first), and the limits are recomputed.
5. A step needs more than two points between its limits.

Limits set by hand (in °C or min) replace steps 1–5; only the characteristics are computed then.

**Reference:** none cited for the detection algorithm.

**Validation:**

- `tests/test_tga.py::StepTest::test_oxalate_three_steps_match_stoichiometry` – the synthetic calcium-oxalate run
  (10 K/min, N₂) gives exactly 3 steps whose losses are within 0.5 percentage points of 12.33, 19.17 and 30.12 %.
- `tests/test_tga.py::StepTest::test_manual_limits` – limits 300–560 °C give one step of 19.17 % ± 0.6.
- `tests/test_dataset.py::DatasetRun::test_oxalate_dataset_same_steps_as_csv` – the same data read from a dataset give
  identical steps.

## 5 Step characteristics: onset, endset, midpoint, peak

`steps.characterise`, for a step between indices a and b:

| Value | Definition |
|---|---|
| Loss | L = m(a) − m(b) in percentage points; in mg from the mg curve |
| DTG peak | point p of maximum loss rate in [a, b]: T_peak, t_peak, rate_peak (%/min), rate_peak_T (%/°C) |
| Midpoint | temperature (and time) where the mass has fallen by L/2 from m(a), linear interpolation |
| Inflection point | on the temperature axis: point q in [a, b] of largest −dm/dT (dm/dT from section 3, i.e. the local heating rate enters through the chain rule); reported as `T_inflection`. On the time axis (isothermal step): q = p |
| Tangent | through (x_q, m_q) with slope s = dm/dT at q (time axis: s = −r_p). Fallback if dm/dT is undefined in the whole step: s = −r_p / β_step with β_step the mean heating rate of the step |
| Baselines | straight lines fitted to w = max(5, 0.25·(b − a)) points before a and after b; a fitted line is used only if \|slope\| ≤ 0.1·\|s\|, otherwise a horizontal line through m(a) or m(b) |
| Onset | intersection of the tangent with the baseline before the step: x_on = (c_base − c_tan) / (s − s_base) |
| Endset | intersection of the tangent with the baseline after the step |

x is the temperature when β_step > 0.3 K/min, otherwise time (then onset/endset are times). An onset is reported only
if it lies between x(a) − 0.5·(x(b) − x(a)) and x_q; an endset only between x_q and x(b) + 0.5·(x(b) − x(a)).
Otherwise the value is left empty.

The inflection point and the tangent slope are taken on the actual temperature axis (local dm/dT), so a heating rate
that changes within the step does not bias the onset. Up to module 0.12.0 the tangent went through the DTG peak
(maximum of dm/dt) with the slope −r_p/β_step (step-average heating rate); with a constant heating rate both give the
same result (the synthetic oxalate onsets are unchanged to 0.001 K), with a varying heating rate the old construction
was wrong (example in the validation below: 389.3 °C instead of 384.0 °C). The DTG peak T_p is still the maximum of
dm/dt.

**Reference:** ISO 11358-1:2022, cited in `steps.py` and in every report ("intersection of the tangent at the
inflection point of the TG curve over temperature with the extended baseline before and after the step").
`refs.py` also contains ASTM E2550-21, but no computation or report cites it.

**Validation:**

- `tests/test_known_answers.py::OnsetKnownAnswer::test_constant_heating_rate` – a step with compact support
  m(T) = 100 − L·S((T − T₀)/h), S′(u) = 15/16·(1 − u²)² (L = 40 %, T₀ = 400 °C, h = 30 K, flat baselines): the
  inflection tangent meets the baselines analytically at T₀ ∓ 8h/15 = 384.0 / 416.0 °C; required within 0.1 K
  (obtained 383.97 / 416.03 °C); inflection at 400.0 ± 0.1 °C.
- `tests/test_known_answers.py::OnsetKnownAnswer::test_variable_heating_rate_uses_local_slope` – the same step with a
  heating rate rising from 5 to 20 K/min across it (sigmoid in T): onset/endset within 0.1 K of 384.0 / 416.0 °C
  (obtained 383.95 / 416.05 °C; the 0.12.0 construction gave 389.3 / 413.5 °C).
- `tests/test_tga.py::StepTest::test_oxalate_three_steps_match_stoichiometry` – for each step
  T_onset < T_peak < T_endset.
- `tests/test_golden.py::GoldenBundle::test_bundle_de` and `::test_bundle_en` – regression only: they fix the
  values of the synthetic oxalate run (onsets 160.7 / 459.4 / 675.7 °C, peaks 188.5 / 498.5 / 738.5 °C, endsets
  209.1 / 523.5 / 781.8 °C, losses 12.15 / 19.30 / 29.84 %). A change in the algorithm changes these numbers and
  fails the test; the numbers themselves are not ground truth. (Unchanged by the 0.13.0 tangent change, because the
  oxalate run has a constant heating rate.)

## 6 T at x % loss, residue, isothermal loss

`steps.loss_temperatures`, `steps.residue`, `steps.isothermal`:

- **T at x % loss** for x = 1, 2, 5, 10, 50: first crossing of m = m_start − x, linear interpolation between the
  two neighbouring points. m_start is the median of the first three points, so x is measured from the initial
  plateau, not from exactly 100 %. Empty if the level is not reached.
- **Residue at the end:** median of the last three points (% and mg), with the last temperature.
- **Residue at a chosen temperature:** mass at the first point with T ≥ the chosen value (no interpolation).
- **Isothermal loss:** for each isothermal segment with at least 5 points, m(start) − m(end); optionally the loss
  after a given hold time (linear interpolation).

**Reference:** none cited.

**Validation:**

- `tests/test_tga.py::StepTest::test_loss_temperatures_increase` – T₁ ≤ T₂ ≤ T₅ ≤ T₁₀ ≤ T₅₀.
- `tests/test_tga.py::StepTest::test_oxalate_three_steps_match_stoichiometry` – end residue within 1.0 of
  100 − 12.33 − 19.17 − 30.12 = 38.38 %.
- Golden tests (regression): T₁ 149.5, T₂ 161.2, T₅ 179.5, T₁₀ 200.8, T₅₀ 740.9 °C, residue 38.38 %.
- Not covered: residue at a chosen temperature, isothermal loss.

## 7 Composition (ASTM E1131, ASTM D7582, free limits)

`composition.compose`. All values are percentage points of the reference mass. m(T) is the mass at the first point
with T ≥ the limit (no interpolation). "Switch" is the first gas change in the gas column, or a time entered by hand.
m_start is the median of the first three points; m_end the median of the last three.

**ASTM E1131 template** (defaults T1 = 200 °C, T2 = 600 °C; T1 is searched only before the switch):

| Row | Value |
|---|---|
| Moisture / highly volatile | m_start − m(T1) |
| Medium volatile (polymer) | m(T1) − m2, with m2 = mass at the switch, else m(T2) (else the last point, with a warning) |
| Combustible (carbon black) – only with a switch | m2 − m_end |
| Ash / filler – only with a switch | m_end |
| Residue (filler, ash, carbon) – without a switch | m2, with a warning that carbon and ash are not separated |

**ASTM D7582 template** (proximate analysis; defaults T1 = 107 °C, T2 = 950 °C). All rows are on the
**as-determined basis**, i.e. in percent of the analysis sample as weighed, taken as the mass at the start
(m_start); with s = 100/m_start:

| Row | Value |
|---|---|
| Moisture M | s·(m_start − m(T1)) |
| Volatile matter VM | s·(m(T1) − m2) (m2 as above) |
| Ash A – only with a switch | s·m_end |
| Fixed carbon FC – only with a switch | 100 − (M + VM + A) ("by difference", all on the same basis) |
| Dry basis (column "trocken"/"dry") | X_d = X · 100 / (100 − M) for every row except moisture; FC_d = 100 − VM_d − A_d follows |

When the reference mass is the sample mass, m_start ≈ 100 % and s ≈ 1. If the protocol sets the reference mass
elsewhere (e.g. at 120 °C), m_start ≠ 100 % and the module rescales to m_start and warns, so that the four
as-determined values add up to 100 % and the bases are not mixed (up to 0.12.0 the rows were in percent of the
reference mass while fixed carbon was 100 − …, which mixed the bases in that case). The dry-basis values were
computed but not shown up to 0.12.0; they are now in the interface table and the report table, with a note on the
basis. Without a switch the D7582 template gives no ash and no fixed carbon and says so. The temperature limits are
defaults of the module and can be changed; they are not taken from the standards' text by the code.

**Free limits:** losses between consecutive user limits (default 200, 400, 600 °C), the loss from the last limit to
the end, and the end residue.

**Reference:** ASTM E1131-20 (`astm-e1131`) and ASTM D7582 (`astm-d7582`, edition year not recorded; marked
"current edition" in `refs.py` for the user to fill in). That D7582 reports fixed carbon by difference on the
as-determined basis and converts to the dry basis with 100/(100 − M) is the conventional proximate-analysis
definition; the text of the standard was not available offline and was not compared.

**Validation:**

- `tests/test_tga.py::StepTest::test_e1131_composition` – synthetic filled elastomer (20 K/min, N₂ → air at 600 °C;
  0.8 % moisture, 12 % plasticiser, 48 % polymer, 30 % carbon that burns only in air): four rows, sum 100 ± 0.5,
  combustible carbon 30 ± 1.5 %.
- `tests/test_known_answers.py::D7582Basis::test_as_determined_and_dry` – synthetic coal (moisture 5 %, volatiles
  30 % to 950 °C in N₂, fixed carbon 50 % burning after the switch to air, ash 15 %): M 5.00, VM 30.00, A 15.00
  (± 0.01), FC 50.00 (± 0.02); dry VM 31.58, FC 52.63, A 15.79 (= X·100/95).
- `tests/test_known_answers.py::D7582Basis::test_reference_mass_not_at_start_is_rescaled` – the same run with the
  reference mass at 120 °C gives the same as-determined values, sum exactly 100, and a warning.
- Not covered: free limits.

## 8 Stoichiometry (content from a step)

`composition.reactions`, `content_from_loss`:

theoretical loss L_th = 100 · Σ νᵢ·M(gasᵢ) / M(starting material)

content = 100 · L_measured / L_th

Molar masses are summed from abridged standard atomic weights in `composition.ATOMIC_WEIGHT` (formula parser handles
brackets, hydrates with `·` or `*`, and leading coefficients). Built-in decompositions:

| Key | Reaction | Gas released |
|---|---|---|
| caco3 | CaCO₃ → CaO + CO₂ | CO₂ |
| mgco3 | MgCO₃ → MgO + CO₂ | CO₂ |
| dolomit | CaMg(CO₃)₂ → CaO + MgO + 2 CO₂ | 2 CO₂ |
| caoh2 | Ca(OH)₂ → CaO + H₂O | H₂O |
| mgoh2 | Mg(OH)₂ → MgO + H₂O | H₂O |
| ath | Al(OH)₃ → ½ Al₂O₃ + 1½ H₂O | 1.5 H₂O |
| boehmit | AlO(OH) → ½ Al₂O₃ + ½ H₂O | 0.5 H₂O |
| gips | CaSO₄·2H₂O → CaSO₄ + 2 H₂O | 2 H₂O |
| gips_halb | CaSO₄·2H₂O → CaSO₄·0.5H₂O + 1.5 H₂O | 1.5 H₂O |
| kaolinit | Al₂Si₂O₅(OH)₄ → metakaolin + 2 H₂O | 2 H₂O |
| talk | Mg₃Si₄O₁₀(OH)₂ → 3 MgSiO₃ + SiO₂ + H₂O | H₂O |

## 10 Reference library

### The built-in library is modelled, not measured

`tga/data/referenzen.json` (built by `tools/build_refs.py`) holds 71 entries with 102 steps from 67 sources. Each
step gives a DTG peak temperature and a mass loss, usually an onset and an end temperature, and each entry gives
atmosphere, heating rate, residue and a structured source. The file states that the values were taken from text and
tables of the sources, not from figures, and that they should be checked against the source before reliable use.
Of the 71 entries, 11 have no DOI in their source and one has no atmosphere.

From these numbers a DTG curve is **calculated** (`library.model_dtg`) on a 1 K grid from 25 to 1000 °C:

- each step is one Fraser–Suzuki peak (section 15) with area = published loss and the peak at T_peak;
- half-widths: left = 0.94·(T_peak − T_onset), right = 0.94·(T_end − T_peak), at least 2 K. The factor 0.94 =
  1.1774/1.2533 is derived in the code for a Gaussian DTG, where the tangent onset lies σ·√(π/2) before the peak and
  the half width at half maximum is 1.1774·σ;
- if only one side is known, the other is set with a ratio of 1.4 (left wider than right); with neither, 25 K on
  each side (8 of the 102 steps);
- each peak is rescaled so that its integral over the grid equals the published loss; the model TG is
  100 − cumulative integral of the DTG.

What this implies for your results:

- A model curve has the published step positions and losses but not the published curve shape. Shoulders, tails,
  overlap and baseline drift of a real measurement are absent.
- The model is valid only for the atmosphere, heating rate, sample mass and crucible of the source. The search flags a
  different atmosphere or heating rate but does not correct for them.
- A high score against a model entry means "consistent with the published step values", not "identified".
- For a result you want to report as an identification, measure your own reference material and store it as a
  measured reference in an own library.

### Own libraries

Measured references store the run's T and mass-% curve (`Library.add_curve`); their DTG is computed like the query
DTG (section 11). Step-value references typed in by the user are modelled exactly like the built-in library.
Steps of measured references are derived from their DTG (`search.steps_from_dtg`: peaks ≥ 5 % of the maximum, loss
= DTG integral between the neighbouring minima, steps < 0.5 % dropped).

**Reference:** Fraser & Suzuki (1969) for the peak shape (cited in `library.py`). The width rule has no cited source.

**Validation:**

- `tests/test_tga.py::LibraryTest::test_every_model_entry_is_sourced` – more than 50 entries, each with a source title
  or authors, each marked as modelled, sum of losses ≤ 101 %.

## 11 Library search score

`search.query`, `search.search`.

**Query:** DTG of the processed run on the 1 K grid 25–1000 °C (`library.dtg_of_curve`): first heating only, mass %
interpolated on the grid, Savitzky–Golay first derivative over 9 points (order 2), sign reversed. NaN outside the
measured range. At least 30 grid points are required.

**Curve score:** for each integer shift s from −S to +S K (S default 20, limited to 0–60) the reference DTG g is shifted
and compared with the query q over the measured range W:

cos(s) = Σ_W q·g_s / (‖q‖·‖g_s‖_W)

coverage(s) = Σ_W max(g_s, 0) / Σ_all max(g, 0)

curve = 100 · max over s of [cos(s) · √coverage(s)]

**Step score:** query steps with loss ≥ 0.5 % and reference steps with loss ≥ 1 % are used. Each reference step is
paired with the query step nearest to T_peak,ref + s (s from the best curve shift). Penalties (each capped at 9):

- paired step: ((T_q − T_r − s)/15 K)² + ((L_q − L_r)/4 %)²
- reference step with no query step at all: 9
- unpaired query step with loss ≥ 3 %: (L_q / 4 %)²
- residue, if both are known: ((res_q − res_r)/4 %)²

step = 100 · exp(−½ · mean of the penalties)

**Hit score:** w·curve + (1 − w)·step (mode "both"; "curve" or "steps" alone are also possible), multiplied by 0.85
when the atmosphere classes (inert / oxidative) differ. w defaults to 0.6 and can be set in the search options
("Gewicht DTG-Kurve [%]", 0–100 %); the server passes it to the search (`w_curve`, refused outside 0–1; up to 0.12.0
the server ignored it and always used 0.6) and returns it with the result; the report's methods text states the
weighting used. Warnings are attached when atmospheres differ, when the heating rates differ by more than a factor
1.5, or when less than 80 % of the reference loss lies in the measured range. The 25 best hits are returned. The
widths 15 K, 4 %, 4 % are fixed in the code.

**Reference:** principle after Schindler et al. (2017) (curve comparison plus comparison of characteristic values),
cited in `search.py` and in the report. The specific scores and weights above are the module's own; the code cites
no source for them.

**Validation:**

- `tests/test_tga.py::LibraryTest::test_search_ranks_oxalate_first` – the synthetic oxalate run ranks a calcium-oxalate
  model entry first with a score > 80, marked as modelled.
- `tests/test_tga.py::LibraryTest::test_own_library_measured_curve_wins` – a run stored as a measured reference is
  found first with a score > 95.
- `tests/test_tga.py::ServerTest::test_flow` – the same through the HTTP interface, own reference ahead of the model
  library.
- `tests/test_tga.py::BundleTest::test_search_hits_cited` – hits and the word "modell" reach the report.
- `tests/test_tga.py::ServerTest::test_search_weight_passed` – for w = 1, 0 and 0.3 sent to `/api/search`, every
  hit satisfies hqi = f·(w·curve + (1 − w)·step) within 0.02 (f = 0.85 for a different atmosphere, else 1); w = 1.5
  is refused.

Note: these tests use a query generated by the module itself, so they show self-consistency, not discrimination
between similar real materials.

## 12 Mixture fit

`search.mixture`:

1. Candidates: the 14 best single hits by curve score, plus the 7 best hits for the positive residual after
   subtracting the least-squares-scaled best hit. Each candidate keeps its own best shift.
2. For every subset of 1 to k candidates (k default 3, at most 4; drawn from the first 24 candidates, or the first 16
   when up to 4 components are allowed) the
   non-negative least-squares weights w are found by solving the normal equations on every subset of active
   components and keeping the all-positive solution with the largest explained sum of squares
   gain = 2·wᵀb − wᵀGw (G = XXᵀ, b = Xq over the measured range). Combinations with a zero weight are discarded.
3. Score = 100·gain / ‖q‖² (share of the query DTG's squared norm explained, not centred).
4. Ranking uses a parsimony penalty: 100 − (100 − score)·(1 + 0.5·(k − 1)).
5. Because every reference DTG is in % of its own mass, the weights are mass fractions. inert = max(0, 1 − Σw).
   Predicted residue = Σ wᵢ·residueᵢ + 100·inert. A note is shown if Σw > 1.15.

**Reference:** none cited for the fitting procedure.

**Validation:** `tests/test_tga.py::LibraryTest::test_mixture_recovers_two_components` – a query built as
0.7·(PE-HD model DTG) + 0.3·(CaCO₃ model DTG) gives a best combination of exactly these two entries with Σw = 1.0 ±
0.1. The test does not check the individual fractions (running it returns 0.70 and 0.30). It uses model curves for
both the query and the library.

## 14 Kinetics

`tga/kinetics.py`; at least three runs with different heating rates over one step. Options in `opts` of
`kinetics.run_all` / `POST /api/kinetics` (not offered in the interface): `ofw` = `"e1641"` (default) or `"doyle"`;
`lifetime` = `"toop"` (default) or `"model"`; `alpha_f`, `T_use`, `t_target_h`, `model`.

### Conversion

For each run, between T_lo and T_hi, first heating only (`conversion`):

α(T) = (m₀ − m(T)) / (m₀ − m₁), m₀ and m₁ the medians of the first and last three points in the window

α is clipped to [0, 1], smoothed (Savitzky–Golay, window max(5, n/60), order 2) and made monotonic (running maximum).
dα/dt = (dα/di)/(dt/di) with a Savitzky–Golay derivative (window max(5, n/40)), converted to s⁻¹. β is the heating
rate from the file, else the median dT/dt in the window. At least 20 points and 0.5 % loss in the window are
required. Temperatures and rates at α = 0.05, 0.10, …, 0.95 are interpolated linearly.

### Isoconversional methods (per α, linear regression across the runs)

| Method | Regression | Eₐ from slope k |
|---|---|---|
| Friedman | ln(dα/dt)_α vs 1/T_α | Eₐ = −k·R |
| Ozawa–Flynn–Wall (default `ofw="e1641"`) | ln β vs 1/T_α | Eₐ = −k·R / b(x), iterated (below) |
| Ozawa–Flynn–Wall (option `ofw="doyle"`) | ln β vs 1/T_α | Eₐ = −k·R / 1.052 (Doyle approximation, constant factor; uncorrected) |
| Kissinger–Akahira–Sunose | ln(β/T_α²) vs 1/T_α | Eₐ = −k·R |
| Starink | ln(β/T_α^1.92) vs 1/T_α | Eₐ = −k·R / 1.0008 |
| Vyazovkin | minimise Φ(E) = Σᵢ Σⱼ≠ᵢ I(E,T_α,ᵢ)·βⱼ / (I(E,T_α,ⱼ)·βᵢ) | golden-section search |

**Temperature integral.** I(E,T) = ∫₀ᵀ exp(−E/RT′) dT′ = (E/R)·p(x), x = E/(RT), with the Senum–Yang rational
approximation of 4th degree p(x) = e^(−x)/x · (x³ + 18x² + **86**x + 96)/(x⁴ + 20x³ + 120x² + 240x + 120).
Up to 0.12.0 the code had **88**x in the numerator (a transcription error): p(x) was then 0.13 % too large at x = 30
and 0.5 % at x = 10 instead of < 10⁻⁸ and < 10⁻⁶; the effect on Vyazovkin Eₐ was below 0.05 kJ/mol on the test
series because the error varies slowly with x.

**OFW iteration (ASTM E1641 procedure).** From ln β = const + ln p(x), the slope gives Eₐ = −R·k / b with
b(x) = −d ln p/dx = e^(−x)/(x²·p(x)) (exact, because dp/dx = −e^(−x)/x²). Start: b = 1.052 (Doyle; in log₁₀ form
0.457 as in the first step of E1641). Then repeat: x = Eₐ/(R·T_c), b = b(x), Eₐ = −R·k/b, until Eₐ changes by less
than 0.01 % (at most 50 steps); T_c is the mean of the runs' T_α taken as 1/T_c = mean(1/T_α,i), the centre of the
regression. b is computed from the Senum–Yang p(x), not read from the table in E1641 (that table was not available
offline and was not compared); which temperature E1641 uses for x (possibly the one at the heating rate nearest the
middle of the range) was not verified, the module uses the centre of the regression. Doyle's 1.052 equals b(x) at x ≈ 37; at x ≈ 30 the exact factor is
1.065, so the uncorrected OFW value is about 1.2 % too high there (option `ofw="doyle"`, kept for comparison with
software that reports the uncorrected value). The standard error is divided by the final b. Each OFW row carries
the final `b`.

**Vyazovkin.** This is the basic integral non-linear method (Vyazovkin 1997) in its form for linear heating: the
integral runs from 0 to T_α with the Senum–Yang approximation, not stepwise over small Δα (the "advanced" method of
Vyazovkin 2001, which is not implemented and no longer cited; up to 0.12.0 the code cited the 2001 paper). The 1997
paper evaluates the integral for arbitrary temperature programs; the module assumes the constant heating rate β of
each run. The search interval is [max(5 kJ/mol, 0.3·E₀), min(1500 kJ/mol, 2.5·E₀)] with E₀ the KAS value at that α
(at least 10 kJ/mol; 150 kJ/mol if KAS gives no value), tolerance 1 J/mol.

**Confidence interval** (Friedman, OFW, KAS, Starink): ±t·SE(k)·R (divided by the same factor as Eₐ), SE the standard
error of the slope, t = t₀.₉₇₅ (two-sided 95 %) for ν = n − 2 degrees of freedom (n = number of runs), from the table
in `tga/tdist.py`: exact values (6 decimals) for ν = 1–30, 40, 60, 120 and ∞, linear interpolation in 1/ν in between
(error < 6·10⁻⁵ against scipy). Up to 0.12.0 t was tabulated only for ν = 1–10, 2.0 was used for 11–30 (true 2.201 …
2.042) and 1.96 above 30. With three runs (ν = 1) t = 12.706. The Kissinger interval uses the same table. Vyazovkin
values have no interval. The result carries `t95` and `dof`.

**Summary:** mean, sample standard deviation, minimum and maximum of Eₐ over 0.1 ≤ α ≤ 0.9.

### Single-value methods

- **Kissinger:** T_p = temperature of the maximum dα/dt in the window, per run; regression of ln(β/T_p²) on 1/T_p;
  Eₐ = −k·R; A = (Eₐ/R)·e^(intercept) (β in K/min, converted to s⁻¹), which assumes a first-order reaction. 95 %
  interval as above.
- **Coats–Redfern:** for the run with the middle heating rate, 0.1 ≤ α ≤ 0.9, each of 14 reaction models:
  regression of ln(g(α)/T²) on 1/T; Eₐ = −k·R; A = β·(Eₐ/R)·e^(intercept). Models: F1, F2, F3, R2, R3, A2, A3, A4,
  D1, D2, D3, D4, P2, P3 (f(α), g(α) in `kinetics.MODELS`, commented as ICTAC 2011 Table 1). Ranked by R².
- **Master plot:** y(α) = (dα/dt)·exp(E/RT), normalised at α = 0.5, with E = mean Friedman Eₐ (else KAS), averaged
  over the runs for α = 0.1 … 0.9; compared with f(α)/f(0.5) of each model by RMS difference. The best model is used
  for the pre-exponential factor (and for the lifetime option `lifetime="model"`) unless the user chooses one.
- **Pre-exponential factor:** ln A(α) = Friedman intercept − ln f(α) for the chosen model; the median over α is used
  for the model-based lifetime option.
- **Compensation effect:** straight line ln A = a·Eₐ + b through the Coats–Redfern results (at least three models).

### Lifetime estimate

**Default (`lifetime="toop"`, `kinetics.lifetime_toop`), model-free:**

t_f(T) = (Eₐ/(R·β)) · p(Eₐ/(R·T_c)) · exp(Eₐ/(R·T))

This is the Toop relation that ASTM E1877 builds on. It follows from g(α_f) = (A·Eₐ/(R·β))·p(x_c) (integral form at
the temperature T_c where the dynamic run reaches α_f) and t_f = g(α_f)/(A·exp(−Eₐ/RT)), so A and the reaction
model cancel. Eₐ is the OFW value at α_f (iterated as above, from a regression at exactly α_f); T_c is each run's
temperature at α_f; ln[(Eₐ/(Rβ))·p(x_c)] (β in K/min, so t in min) is computed for every run and averaged (for
consistent data all runs give the same value; the spread is returned as `lnC_spread`). Defaults: α_f = 0.05, T = 50,
100, 150, 200 °C. Temperature index for a target life t* (h): T_index = Eₐ / (R·(ln(60·t*) − ln C)) − 273.15.

**Option `lifetime="model"` (`kinetics.lifetime`, the 0.12.0 method):** t_f = g(α_f) / k(T), k(T) = A·exp(−Eₐ/RT),
with Eₐ the mean Friedman value (else KAS) over α = 0.1–0.9, ln A the median from the Friedman intercepts, the model
from the master plot.

**Not checked against the standard.** The text of ASTM E1877 (and of the E1641 table it uses) was not available
offline; the relation above was derived from the integral rate law, and whether E1877 prescribes exactly this
choice of Eₐ, T_c and heating rate was not verified. The interface, the report text and this page say so. Either way
it is an extrapolation far below the measured temperatures; the report text says it is only an indication.

## 15 Fraser–Suzuki deconvolution

`tga/deconv.py`, peak shape in `library.fs_peak`. The fit is made to the DTG −dm/dT (%/°C) between the chosen
limits; isothermal points (NaN) are dropped.

Peak with position x₀, area A, left and right half widths at half maximum h_l, h_r:

a = ln(h_r/h_l), w = 2a·h_r/(eᵃ − 1)

y(x) = exp(−ln 2 · [ln(1 + 2a(x − x₀)/w) / a]²) for 1 + 2a(x − x₀)/w > 0, else 0

normalised by its integral (w/2)·√(π/ln 2)·exp(a²/(4 ln 2)), so that the area equals A. For h_l = h_r a Gaussian is
used. The area of each fitted peak is its mass loss in %.

Fit: Levenberg–Marquardt with a forward-difference Jacobian (step 10⁻⁴·max(1, |p|)), Marquardt scaling, λ starting at
10⁻², at most 200 iterations; bounds by clipping: x₀ within the data range, 0 ≤ A ≤ 100, 1 K ≤ h ≤ half the range.
Positions can be fixed. Start areas default to the total DTG area divided by the number of peaks. R² = 1 − SSR/SST.
Start values can be proposed from minima of the second derivative (Savitzky–Golay, 15 points, order 3; up to 4 peaks
above 5 % of the maximum). Biomass template start values: hemicellulose 290 °C (h_l 35, h_r 25 K), cellulose 350 °C
(22, 15 K), lignin 380 °C (120, 120 K). No uncertainties of the fitted parameters are computed.

**Reference:** Fraser & Suzuki (1969); procedure after Perejón et al. (2011); biomass template concept after Yang et
al. (2007). Levenberg–Marquardt: no reference cited.

**Validation:** `tests/test_tga.py::DeconvTest::test_three_overlapping_peaks` – noise-free sum of three Fraser–Suzuki
peaks (300 °C/30 %, 350 °C/40 %, 380 °C/20 %) fitted from offset start values: R² > 0.999, positions within ±2 K, areas
within ±1.5. Not covered: noisy data, fixed positions, the biomass template, the start-value proposal.

## 16 DSC heat-flow evaluation

`tga/dsc.py`, for runs with a heat-flow column (simultaneous thermal analysis). Units mW, W/g or µV (µV: uncalibrated
DTA signal, area only). Sign convention selectable: exo up (default) or endo up. A range needs at least 12 points;
if the temperature passes through it more than once, only the first contiguous run of points is used.

**Peak:**

- linear baseline over **time** between the means of the first and last e points of the range, e = max(3, n/40);
- d = signal − baseline; the peak is the point of largest |d|; endothermic or exothermic from its sign and the
  convention;
- area = |∫ d dt| (trapezoid, t in s): mJ (mW), J/g (W/g) or µV·s;
- ΔH = area / m₀ in J/g for mW (needs m₀), = area for W/g; signed value endothermic positive;
- onset/endset: on each side of the peak, the point of largest |dd/dT| (with the sign of the peak), tangent
  intersected with d = 0: T = T_j − d_j / (dd/dT)_j; kept only within the range ± 1 K.

**Glass transition:** baselines fitted to the first and last quarter of the range (at least 4 points each); midline
= mean of the two baselines; T_g (midpoint) = first crossing of the signal with the midline, linear interpolation;
step height = difference of the baselines at T_g; onset/endset from the tangent at the steepest point (inner range)
intersected with each baseline; Δc_p = |step| / m₀ / β (mW; β in K/s) or |step| / β (W/g), in J/(g·K).

The instrument's temperature and heat-flow calibration is used as it is; the module has no calibration step and the
methods text says so.

**Reference:** ISO 11357-1:2023 (peak integration, extrapolated onset/endset), ISO 11357-2:2020 (glass transition),
cited in `dsc.py` and in the report; ASTM E967 and ASTM E793 are listed in `dsc.REFS` (no edition year).

**Validation** (synthetic signal: sloped baseline, Gaussian peak σ = 3 K at 160 °C with area 50 mJ, β = 10 K/min,
m₀ = 10 mg):

- `tests/test_dsc.py::DSC::test_peak_area_and_temperatures` – endothermic; area 50.0 ± 0.5 mJ; ΔH 5.0 ± 0.05 J/g;
  T_peak 160.0 ± 0.1 °C; onset 154.0 ± 0.3 °C and endset 166.0 ± 0.3 °C (tangent at Tp ∓ σ meets the baseline at
  Tp ∓ 2σ).
- `tests/test_dsc.py::DSC::test_exo_and_sign_convention` – exothermic 30 mJ, endo-up file: signed ΔH −3.0 ± 0.05 J/g.
- `tests/test_dsc.py::DSC::test_noise_and_units` – with noise ΔH 5.0 ± 0.1 J/g; µV gives no ΔH.
- `tests/test_dsc.py::DSC::test_glass_transition` – T_g 100.0 ± 0.3 °C, step 0.15 ± 0.01 mW,
  Δc_p = 0.15/10/(10/60) = 0.09 ± 0.01 J/(g·K), onset < T_g < endset.
- `tests/test_dsc.py::DSC::test_analysis_and_errors`, `tests/test_dsc.py::DSCReport::test_csv_with_heat_flow_and_bundle`
  – errors per range, variables, report content.

## 17 TGA–FTIR: Gram–Schmidt curve

`tga/egs.py`. Input: a series of absorbance spectra (CSV/TXT matrix time × wavenumber, also transposed; or JCAMP-DX
with one block per time, uncompressed `XY..XY` or `X++(Y..Y)`; compressed ASDF data are refused). Time in min (s if
the header says so). A wavenumber axis must lie within 200–8000 cm⁻¹ and span more than 300 cm⁻¹.

- **Gram–Schmidt intensity:** the first k spectra (default 5; at most n − 2) span a background subspace (orthonormal
  basis by QR decomposition). For each spectrum y, GS = ‖y − Q·Qᵀ·y‖. The code applies this to absorbance spectra,
  not to interferograms.
- **Spectrum at a time:** nearest recorded spectrum minus the mean of the first k spectra (optional).
- **Chemigram:** ∫ A dν̃ over a chosen wavenumber band (trapezoid), per time.
- The spectrum can be passed to the FTIR module as JCAMP-DX.

The gas analysis does not go into the report.

**Reference:** de Haseth & Isenhour (1977), cited in `egs.py`.

**Validation:**

- `tests/test_egs.py::EGS::test_gram_schmidt_maximum` – synthetic CO₂ evolution (Gaussian in time at 18 min): GS
  maximum at 18 ± 0.7 min; background spectra give GS < 10⁻⁹; two evolutions at 10 and 28 min found within ± 0.8 min.
- `tests/test_egs.py::EGS::test_spectrum_and_chemigram` – band maximum at 2348 ± 8 cm⁻¹; background removed below
  1000 cm⁻¹ (< 10⁻⁶); chemigram 2250–2450 cm⁻¹ peaks at 18 ± 0.7 min.
- `tests/test_egs.py::EGS::test_transposed_and_jcamp`, `::test_compressed_jcamp_reported`, `::test_errors`,
  `::test_jcamp_opens_in_ftir` – input formats and hand-over to the FTIR reader.

## 18 Runs from datasets

`tga/dataset.py`: a dataset from the Datenaufbereitung module is turned into a run. The user assigns columns to roles.
Units are checked by dimension and converted: time → min, sample/program temperature → °C (a column marked as a
temperature difference is refused), mass → mg (mass unit) or % (dimensionless unit other than "1", e.g. %, ‰, ppm),
gas flow → ml/min. DTG, heat flow and segment columns are passed through with their unit; gas must be a text column.
A column without a unit, a unit of the wrong dimension, or one column in two of the roles time/temperature/mass is
refused. Rows marked as excluded are left out. Sample mass (mass unit, name like Einwaage, sample mass, m0), heating
rate (unit compatible with K/s, name like rate, heating, ramp, beta) and gas are taken from the dataset's conditions.
The run is stored as a small JSON file (`folio-tga-dataset/1`) that is read back through the same reader path; ID,
version, live/pinned mode and column origin are kept in the run's metadata and named in the methods text.

**Reference:** none cited.

**Validation:**

- `tests/test_dataset.py::DatasetRun::test_oxalate_dataset_same_steps_as_csv` – identical steps, onsets, peaks,
  endsets and residue (± 10⁻⁶) as the CSV file; *m₀* 10.0 mg and 10.0 K/min from the conditions.
- `tests/test_dataset.py::DatasetRun::test_units_converted` – s, K and g give the same steps (loss ± 0.005,
  temperatures ± 0.05 °C); a % mass column gives a run in %.
- `tests/test_dataset.py::DatasetRun::test_unit_mismatch_refused` – seven wrong mappings are refused with a reason.
- `tests/test_dataset.py::DatasetRun::test_excluded_rows_restore_refresh_and_report` – excluded row missing; reload;
  report names ID and version; update to a new version.
- `tests/test_dataset.py::DatasetRun::test_gas_text_column_and_extra_roles` – gas text column and program temperature
  in K.

## Known limitations

- **No real instrument files in the tests.** Every reader was built from documented export formats and tested with
  synthetic files written by the tests. The module contains no `tests/README` and no test data from a real
  instrument, so no format can be considered verified with a real file. NETZSCH `.ngb` reading is tested only with a
  replaced `read_ngb`. The TRIOS multi-sheet join is tested only with a synthetic workbook. Check the first runs
  from your instrument against the instrument software before reporting values.
- **Synthetic validation only.** All accuracy tests use noise-free or lightly noisy synthetic data (single-step
  kinetics of known form, Gaussian DSC peaks, Fraser–Suzuki DTG peaks, smooth TG steps). The kinetics known-answer
  data are generated independently of the module's approximations, but they are still ideal single-step data. The
  tests show that the code does what it is meant to do, not how it performs on real, overlapping or noisy data.
- **Onset and endset** are checked against an analytic tangent construction on noise-free synthetic steps
  (section 5). Results on real data depend on the DTG window (default 4 K) and on the baseline rule of section 5.
- **Reader guesses:** a temperature column without unit is read as Kelvin when it starts at 250–330 or its name says
  K, otherwise as °C (a note is shown in both cases); a mass column without a unit in the range 50–120 is read as %;
  for PerkinElmer files the corrected weight is preferred and the unsubtracted one is used only when nothing else is
  there (with a note). Use the column-mapping dialog when in doubt and check the run's info line.
- **Library search** narrows down, it does not identify. The built-in library is modelled from published step
  values, not measured (section 10); step positions depend on heating rate, sample mass, crucible and atmosphere.
  The search tests use queries generated by the module itself.
- **Mixture fit:** fractions are tested only as a sum, on model curves; the score is a non-centred share of explained
  squared norm.
- **Kinetics:** the OFW iteration follows the procedure of ASTM E1641 but computes b(x) from the Senum–Yang p(x)
  instead of the standard's table and evaluates x at the centre of the regression; neither was compared with the
  standard's text. The Vyazovkin implementation is the basic method (integral from 0 to T_α, linear heating; not the
  Δα method) and has no confidence interval. A values and the compensation effect are untested.
- **Lifetime (ASTM E1877):** not checked against the text of the standard. The default uses the model-free Toop
  relation with the OFW Eₐ at the failure conversion; it is an extrapolation far below the measured temperatures.
- **Composition:** free limits, residue at a chosen temperature, isothermal loss, buoyancy correction, resampling,
  blank subtraction, averaging and the two-point calibration have no tests. Masses at temperature limits are taken
  at the first point at or above the limit, without interpolation. The D7582 basis rules (as-determined, fixed
  carbon by difference, dry = ·100/(100 − M)) follow the usual proximate-analysis convention; the standard's text was
  not compared.
- **Edition years** of ASTM E1582, E2040, D7582, E967 and E793 are not recorded; the bibliography entries say
  "current edition" and must be completed by the user before publication.
- **Replicates:** steps are matched by their order.
- **DSC:** no own calibration step (ASTM E967); the instrument calibration is used unchecked.
- **Gas analysis** is not included in the report.
- **No uncertainty propagation** for losses, contents, onset temperatures or deconvolution parameters; only the
  isoconversional and Kissinger activation energies carry a confidence interval.
